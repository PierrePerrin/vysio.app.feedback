# Contributing to Vysio Feedback

Thanks for helping improve **Vysio**!  
This repository is focused on **community feedback**, **bug tracking**, and **feature requests**.

## What to use this repo for

- Reporting reproducible bugs
- Suggesting product improvements
- Sharing workflow pain points for iPad development
- Discussing roadmap priorities

## Before opening a new issue

1. Search existing issues first to avoid duplicates.
2. Confirm you are using the latest TestFlight build (if applicable).
3. Gather key details (device model, iPadOS version, provider, logs/screenshots).
4. Keep one issue per problem/request.

## Bug report quality checklist

A great bug report includes:

- Clear title and concise summary
- Expected behavior vs actual behavior
- Reproducible steps
- Environment details:
  - Vysio app version / TestFlight build
  - iPad model
  - iPadOS version
  - Provider (Codespaces, code-server, Gitpod, custom)
- Attachments (screenshots, screen recordings, logs if available)

## Feature request quality checklist

A strong feature request includes:

- Problem statement (“What workflow pain are you solving?”)
- Proposed solution
- Alternatives considered
- Impact and priority
- Scope (single-user convenience vs broad community value)

## Labels and triage

Maintainers may apply labels such as:

- `bug`
- `feature`
- `needs-triage`
- `needs-info`
- `duplicate`
- `planned`
- `in-progress`
- `released`

Issues missing required details may be marked `needs-info`.

## Response expectations

We read all feedback, but response times may vary depending on:
- Severity
- Reproducibility
- Current roadmap priorities

High-signal reports help us act faster.

## Security issues

Please **do not** post sensitive security vulnerabilities publicly.  
Instead, contact the team privately (add your security email here, e.g. `security@vysio.app`).

## Community conduct

Be respectful and constructive.  
Harassment, spam, and abusive behavior may lead to moderation actions.
